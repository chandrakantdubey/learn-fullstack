## Canonical technology rule

Every technology has one canonical note under `technologies/`. Specialized repositories remain the deep learning source for language/framework mechanics.

## Known intentional alternatives

Alternative technologies are awareness unless a project or architecture decision requires them. Avoid turning the integrated system into a catalog of competing stacks.

## Verification

Coverage is verified through:

1. concept understanding
2. implementation exercises
3. failure/debugging practice
4. production project acceptance criteria
5. interview/system-design defense

## Remaining work after integration

The knowledge graph is integrated. The remaining work is execution rather than repository sprawl:

- build the project portfolio
- run the interview verification loop
- periodically audit links and technology versions
- deepen any source topic discovered to be weak during actual project implementation
